# Report behavior

Source: README.md collection/detection/review contracts and the user's HTML reports and daily delivery milestone.

- Shared ownership: `base.html` navigation, `report.html` report states, `archive.html` archive pagination, `styles.css` tokens and scrollbar baseline, `render.py` factual projections.
- Latest and archived reviews use the same template. Latest means the newest collection timestamp among saved reviews, not the most recently regenerated narrative.
- A static report shows collection time, publication time, and freshness at publication. It makes no live freshness claim after deployment.
- No forms, mutations, loading states, dialogs, selection, or runtime network requests. Links and disclosures use native semantics with visible focus. Empty archive explains that collection must run first.
- Marketer report contract (user request, November 2026): show status, check date, concise pages-checked coverage, priority issues, changes, and next actions. Incomplete checks and unverified findings remain explicit in reports and archive statuses. Saved evidence and integrity checks are unchanged; general specialist links and raw data links are omitted from report pages; the PageSpeed integration task explicitly adds an expandable Lighthouse technical-evidence disclosure. Dates link to reports, with five recent entries and paginated full history. Each issue shows what happened, affected pages, why it matters, and a next action; resolved and unverified issues never present stored older values as current results.
- English, Gregorian dates with explicit Asia/Yerevan zone. Mobile reflow preserves actions/evidence; tables scroll within their own labeled region.
- Accessibility baseline: semantic headings/landmarks, keyboard links/disclosures, visible focus, text status, and WCAG AA contrast. Native controls accept platform-owned behavior.
- Daily Issue summary uses code-derived facts and actions. One run-ID marker prevents duplicates across delivery retries; a failed publication produces an explicit delivery warning instead of linking an older review as current.
- Permission/delivery source: repository workflow and existing `GitHubDelivery`; generated review data remains public under the established public repository contract. No raw response bodies are copied into the Pages artifact.

The report leads with the saved assessment and its headline, followed by one ordered priority list combining reasoning, affected pages, next actions, and completion checks. Individual explanations have no “AI note” labels. In AI mode, issue titles, explanations, recommendations and completion criteria come only from the saved validated narrative. Unverified issue prose is retained alongside its deterministic status. Findings without saved analysis appear as recorded facts in a disclosure, never template-generated issue cards. Legacy AI records without a title use the static label “Recorded finding” and omit absent completion criteria; templates never supplement AI text. In fallback mode, generation stores the deterministic narrative before rendering; only historical fallback records may use the explicit legacy fallback adapter. No suggested owners are displayed. Coverage and confirmed changes remain code-derived and visible. No saved reviews are rewritten or extra model calls made to render the report.

- PageSpeed integration (user task, November 2026): display useful saved laboratory measurements grouped by page with adjacent Mobile/Desktop columns and metric rows; metrics absent from both strategies and noncomparisons are omitted from the primary report. Short path labels link to full URLs; scores use integer /100 values, timings use two-decimal seconds except TBT in integer milliseconds, and CLS uses three decimals. Individual missing values use an explained dash, with unavailable strategies labeled once. All-unavailable runs use a compact completed/planned summary and an allowlisted reason grounded in saved HTTP/error evidence. Mixed runs show one warning within Performance & Lighthouse; the report header does not repeat it. A PageSpeed failure does not change the main SEO audit results or prove a site problem. Failure causes must not be guessed from missing credentials or presumed project quotas. Native details retain per-request HTTP failures, deferred requests, incomplete data, Lighthouse diagnostics, and separately labeled CrUX availability. No fabricated results, live requests, or raw JSON appear in report HTML.
